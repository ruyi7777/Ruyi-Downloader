# 如意视频下载器（Ruyi Video Downloader）

**项目代号：** Ruyi Video Downloader
**项目版本：** V1.0
**文档版本：** V1.0
**开发方式：** Codex + VS Code + Git
**目标平台：** Windows 10 / Windows 11
**主要语言：** Python 3
**GUI 框架：** PyQt6
**核心下载引擎：** yt-dlp
**媒体处理：** FFmpeg
**打包工具：** PyInstaller

---

# 一、项目概述

## 1.1 项目目标

开发一款 Windows 桌面视频下载软件「如意视频下载器」。

软件主要用于通过图形化界面调用 yt-dlp 下载网络视频，并通过 FFmpeg 自动处理音视频合并。

软件需要具备：

* 简洁易用的 Windows GUI
* 视频 URL 输入
* 视频信息解析
* 视频质量选择
* 视频下载
* 音视频自动合并
* Cookie 支持
* 下载进度显示
* 下载任务管理
* 下载目录管理
* 重复文件检测
* yt-dlp / FFmpeg 更新
* 下载日志
* 错误提示
* 多任务下载
* EXE 独立运行
* 后续可扩展更多平台

---

# 二、设计原则

## 2.1 模块化

禁止把所有代码写入 `main.py`。

项目必须按照功能进行模块划分。

推荐：

```text
UI
↓
Core
↓
Services
↓
External Tools
```

---

## 2.2 UI 与业务逻辑分离

界面代码不能直接承担复杂下载逻辑。

例如：

错误：

```text
按钮点击
↓
直接调用 yt-dlp
↓
处理下载
↓
解析进度
↓
修改 UI
```

正确：

```text
按钮
↓
UI
↓
Task Manager
↓
Downloader
↓
yt-dlp Service
↓
yt-dlp
```

---

## 2.3 不破坏已有功能

Codex 修改代码时：

* 不允许为了实现新功能随意删除旧功能
* 不允许未经确认重写整个项目
* 不允许随意改变已有配置文件格式
* 不允许修改无关模块
* 修改后必须进行测试

---

# 九、视频信息解析

用户输入 URL 后点击：

```text
解析
```

软件调用 yt-dlp 获取：

* 视频标题
* 视频作者
* 平台
* 视频时长
* 可用格式
* 分辨率
* 文件大小（如果可获取）
* 缩略图（后续功能）

解析过程中 GUI 不得卡死。

---

# 十、视频质量

提供质量选择：

```text
2160p
1440p
1080p
720p
360p
最佳
```

默认：

```text
1080p
```

如果没有 1080p：

```text
1080p
↓
720p
↓
360p
```

自动向下兼容。

---

# 十一、AV1 处理

对于高分辨率下载，优先避免选择 AV1，除非用户明确选择。

默认策略：

```text
优先 H.264 / VP9
避免 AV1
```

具体格式选择由 yt-dlp format selector 实现。

---

# 十二、音视频合并

如果视频与音频为独立流：

```text
视频
+
音频
↓
FFmpeg
↓
最终 MP4
```

默认输出：

```text
MP4
```

FFmpeg 不存在或无法调用时，应给出明确错误。

---

# 十六、重复下载检测

开始下载前检查目标目录。

如果已经存在相同文件：


```text

覆盖

```


优先使用视频 ID 判断，而不是仅使用文件名。

# 十八、多线程 / 多任务

软件支持同时下载多个任务。

默认：

```text
并发任务数：2
```

用户可以在设置中调整。

例如：

```text
1
2
3
4
```

第一阶段不要实现过度复杂的线程池。

建议使用：

```text
QThread / QThreadPool
```

或者 Qt 合适的异步任务机制。

禁止在 GUI 主线程直接执行长时间下载。

---

# 十九、暂停 / 继续

第一阶段可以不实现真正的暂停。

后续版本可以支持：

```text
暂停
继续
取消
```

如果 yt-dlp 本身的能力允许，应优先复用 yt-dlp 能力，而不是自行实现复杂下载协议。

# 三十二、开发原则总结

如意视频下载器不是一次性脚本，而是按照长期维护的软件进行开发。

核心原则：

```text
简单
稳定
模块化
可维护
可扩展
```

优先保证：

```text
能运行
↓
功能正确
↓
稳定
↓
易维护
↓
再考虑复杂功能
```

不要为了增加功能而牺牲稳定性。
